# .ai-knowledge.md — AI Coding Session Anti-Repetition Guide

## Commands

- Before `git commit`, verify `git config user.name` and `git config user.email` are set. On "Author identity unknown", run `git config user.name "..." && git config user.email "..."` first, then retry — do NOT retry the same `git commit` command.
  - solves: S4
  - attribution_type: time

## Build Gotchas

- After a build failure (e.g., `npm run build` → `SyntaxError`), fix the source code first, then re-run the build. Running the same build command again without modifying the failing source file is a wasted retry.
  - solves: S5
  - attribution_type: time

- After lint errors (e.g., `eslint src/` reports multiple errors), run `eslint --fix src/` to auto-fix all fixable errors in one pass, or manually fix ALL reported errors before re-running eslint. Do NOT fix one error at a time and re-run eslint between each fix.
  - solves: S6
  - attribution_type: time

## Runtimes

- After a test failure (e.g., `jest test/calculator.test.js` → assertion mismatch), modify the implementation code to address the failure, then re-run the test. Running the exact same test command again without changing code is a no-progress retry loop.
  - solves: S7
  - attribution_type: time

## Skill & MCP Usage

- Before using the Edit tool on a file, Read the file first to confirm its current content. If Edit fails with "old_string not found", re-Read the file to get the actual content before retrying — do NOT retry the same `old_string`.
  - solves: S13
  - attribution_type: functional
